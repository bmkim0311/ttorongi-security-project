# Security scenario snapshots

이 디렉터리는 취약점 재현과 보완 전후를 비교하기 위한 **참고용 스냅샷**입니다. 실제 실행 진입점은 `user/`, `admin/`, `partner/`의 현재 코드이며, 이곳의 파일은 개별 시나리오 비교용입니다.

각 폴더는 이름을 통일해 다음 두 파일만 둡니다.

- `vulnerable_snapshot.py`: 취약 동작을 재현하던 상태
- `secured_snapshot.py`: 해당 취약점을 보완한 상태

원본 작업 폴더의 백업 파일은 `before-scenario*-secure`, `before-scenario*-vulnerable`처럼 **변경 직전 상태**를 뜻하는 이름이어서 실제 코드 상태와 파일명이 반대로 보일 수 있었습니다. 포트폴리오 공개본에서는 코드 내용을 직접 대조해 아래 의미에 맞게 다시 분류했습니다.

| 시나리오 | 취약 상태 | 보완 상태 |
| --- | --- | --- |
| A01 | 타 사용자 대여기록 조회/반납 시 소유권 검증 누락 | `user_id` 조건을 포함한 소유권 검증 적용 |
| A02 | 예측/재사용 가능한 QR 토큰 처리 | 랜덤 토큰 검증, 대여소 일치 확인, replay 차단 |
| A03 | 동시 대여 경쟁 구간 및 상태 변경 재검증 부족 | 트랜잭션 잠금과 조건부 UPDATE/영향 행 검사 적용 |
| A04 | `static/exports` 운영자료 직접 접근 가능 | 비로그인 직접 접근 차단 및 보안 이벤트 기록 |
| A05 | 협력업체가 배정되지 않은 자전거 상태까지 변경 가능, 감사로그 부족 | 배정 작업 검증, 잠금, 조건부 변경, 감사 이벤트 기록 |

메인 서비스 코드는 포트폴리오 공개본에서 A01~A05의 **보완 상태를 기준**으로 정리했습니다.
